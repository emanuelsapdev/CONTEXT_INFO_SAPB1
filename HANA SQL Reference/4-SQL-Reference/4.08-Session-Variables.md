# 4.8 Session Variables

> [↑ 4 SQL Reference](README.md) · Fuente: *SAP HANA SQL Reference Guide for SAP HANA Platform (SAP HANA Platform 2.0)*, páginas 73–81

The following table lists predefined session variables and whether they can be set by the user (using a SET statement) or a client (API) call, or whether they are set exclusively by the server.

| **Predefined Variable(M_SESSION_CONTEXT.KEY)** | **Value Constraint** | **Set by** | **In M_SESSION_CONTEXT** | **Description** |
| --- | --- | --- | --- | --- |
| APPLICATION | NVARCHAR(256) | User/Client | Yes | Specifies the application name.<br>**Server usage**: Traces, statistical data and trace filters |
| APPLICATIONVERSION | NVARCHAR(256) | User/Client | Yes | Specifies the application version information. Applications can use their "own" version naming, no format is predefined<br>**Server usage**: Traces, statistical data and trace filters |
| APPLICATIONUSER | NVARCHAR(256) | User/Client | Yes | Specifies the applica tiondefined user name.<br>**Server usage**: Traces, statistical data and trace filters |
| APPLICATIONACTION | NVARCHAR(256) | User/Client | Yes | Specifies that with AP PLICATIONACTION the application can define which logical action/ step it is currently per forming. The usage is up to the application and could be coarse grain like 'create sales order' or fine grain like 'refresh service tab' in SAP HANA Studio.<br>**Server usage**: Traces, statistical data and trace filters |
| APPLICATIONCOMPONENT | NVARCHAR(64) | Client | Yes | Specifies the name of the application component.<br>**Server usage**: Traces, statistical data and trace filters |
| APPLICATIONCOMPONENTTYPE | VARCHAR(32) | Client | Yes | Specifies the type of application component. For example, UPD.<br>**Server usage**: Traces, statistical data and trace filters |
| APPLICATIONSOURCE | NVARCHAR(256) | User/Client | Yes | Specifies that with AP PLICATIONSOURCE the application can de fine from which source file SAP HANA was called.<br>The usage is up to the application and could be something like one of the following examples:<br>• `<abap_program_` `name>`:`<line_nu` `mber>`<br>• `<java_source_f` `ile_name>`:`<lin` `e_number>`<br>• `<package_name>` / `<file_name>`:`<l` `ine_number>`<br>**Server usage**: Traces, statistical data and trace filters |
| CASE_SENSITIVE | VARCHAR(5) | User/Client | Only if set to FALSE | Specifies that with CASE_SENSITIVE set to TRUE, only the exact match is found. With CASE_SENSITIVE set to FALSE, any upper/ lowercase combination of the search string is found. The default is TRUE.<br>If a case-insensitive search or compare is done outside of a filter on a table, the corresponding columns may be returned in upper case. This is because an UPPER function is applied by the optimizer to influence the result to achieve a case-insensitive search. For example, `SELECT * FROM TAB WHERE a` `LIKE '%a%'` works well, but `SELECT *` `FROM tab1 WHERE name LIKE '%case%' UNION SELECT * FROM tab2 WHERE name` `LIKE '%case%'` re turns the results in uppercase due the required union comparison.<br>Also, CASE_SENSITIVE is only supported for VARCHAR, NVARCHAR and SHORTTEXT values |
|   |   |   |   | and only for these operations:<br>• WHERE (including LIKE)<br>• JOIN<br>• HAVING<br>• CASE<br>• GROUP BY<br>• ORDER BY<br>• Window functions<br>• UNION<br>**Server usage**: Defines the case-sensitivity during the search. |
| DATE_FORMAT | - | User/Client | Yes | Specifies the default DATE format to apply for the session.<br>**Server usage**: No |
| DEBUG_TOKEN | VARCHAR(32) | User/Client | Yes | Specifies that with DEBUG_TOKEN you can set a session variable, used by the debugger, to attach criterion.<br>If you specify that the debugger is to only attach to connections where a certain debug token is set, it attaches only to the ones where the DEBUG_TOKEN session variable is set and ignores others.<br>**Server usage**: M_DEBUG_SESSIONS.ATTACH_FILTER_DEBUG_TOKEN |
| PROTOCOL_VERSION | - | Server | Yes | Specifies the protocol version of the client interface libraries, formatted as: `<protocol_version >` (`<distribution_pr` `otocol_version>`, `<data_format_vers` `ion>`). For example, 4.1 (1,1)<br>**Server usage**: Internal |
| SECONDDATE_FORMAT |   | User/Client | Yes | Specifies the default SECONDDATE format to apply for the session.<br>**Server usage**: No |
| SPATIAL_OUTPUT_REPRESENTATION | - | User/Client | Yes | Specifies the output format of ST_Geome try and ST_Point. Valid options are WKB, the default, and EWKB. |
| TEMPORAL_SYSTEM_TIME_AS_OF | - | User/Client | Yes | For use with system-versioned tables. Setting this session variable automatically adds a FOR SYSTEM_TIMEAS OF clause to all system-versioned tables contained in subsequent SELECT statements (assuming a FOR SYSTEM_TIME AS OF is not already specified in the SE LECT statement).<br>**Server usage**: No |
| TEMPORAL_APPLICATION_TIME_AS_OF | - | User/Client | Yes | For use with application-time period tables. Setting this session variable automatically adds a FOR APPLICATION_TIME AS OF clause to all application-time period tables contained in subsequent SELECT statements (assuming a FOR APPLICATION_TIME AS OF is not already specified in the SELECT statement).<br>**Server usage**: No |
| TIME_FORMAT | - | User/Client | Yes | Specifies the default TIME format to apply for the session.<br>**Server usage**: No |
| TIMESTAMP_FORMAT | - | User/Client | Yes | Specifies the default TIMESTAMP format to apply for the session.<br>**Server usage**: No |
| TOTAL_ROWCOUNT | Integer | Server | No, only accessible from: `SELECT` `session_contex t('TOTAL_ROWCOU` `NT') FROM DUMMY`. | Specifies the total row count. Specifying SE LECT ... LIMIT x re turns up to x rows. With the optional TO TAL ROWCOUNT the (estimated) total number of rows is set in TOTAL_ROWCOUNT variable. This variable is not deleted/reset by non TOTAL ROW COUNT statements. The similar SELECT TOP x ... does not support this extension.<br>This feature is only supported for column tables and column views. It can return ex act or estimated row count or only the given LIMIT. The concrete re turn value depends on the statement, used tables and views and internally chosen SQL optimizer strategy. Us age is recommended only for interactive paged searches to show information like "result 11 to 20 of estimated 50000".<br>**Server usage**: SE LECT ... LIMIT x TOTAL ROWCOUNT |
| TRACEPROFILE | - | User/Client | Yes | Specifies the name of the trace profile. This is used for manual activation of trace pro files defined in inifiles as [tracepro file_`<name>`]<br>The value can contain one traceprofile name or a comma separated list of traceprofile names.<br>In SAP HANA Studio, the traceprofiles are accessible as End-To-End Traces.<br>**Server usage**: Trace filter |
